### **Решение**

#### Диаграммы:

- Диаграмма контекста: [Контекст-диаграмма](/out/Task3/context-diagram/context_diagram.png)
- Диаграмма контейнеров: [Контейнер-диаграмма](/out/Task3/context-diagram/context_diagram.png)


#### Компоненты решения:

1. **Клиентские приложения**:
   - **Сайт (PHP + React.js)**: Для новых клиентов. Статический контент + форма заявки.
   - **Интернет-банк (ASP.NET MVC 4.5)**: Для существующих клиентов. Модуль депозитов с персонализированными ставками.
2. **API Gateway**:
   - Терминация TLS, аутентификация, маршрутизация запросов
   - Интеграция: Сайт → Kafka, Интернет-банк → Депозитный сервис (REST)
3. **Депозитный сервис (Java Spring Boot + MS SQL)**:
   - Ядро логики депозитов: управление заявками, расчет ставок
   - Интеграции:
     - **Redis**: Кэширование справочников и ставок
     - **Kafka**: Асинхронное взаимодействие с АБС (отправка заявок, получение статусов)
     - **REST API**: Для интернет-банка и CRM кол-центра
4. **Адаптер АБС (Java + Kafka)**:
   - Буферизует запросы к АБС, преобразует форматы
   - Позволяет АБС работать в своем темпе (вертикальное масштабирование)
5. **АБС (Oracle + PL/SQL)**:
   - Регистрация заявок, открытие депозитов, отправка событий
   - Интерфейс для менеджеров бэк-офиса
6. **СМС-шлюз (Java + Kafka)**:
   - Подписывается на события `deposit_opened`, отправляет SMS через телеком-оператора
7. **CRM кол-центра (React.js + Java Spring Boot)**:
   - Отображение заявок с сайта, инструменты для операторов


#### Обоснование выбора технологий:
- **Java для Депозитного сервиса и Адаптера АБС**: Экспертиза команды АБС (уже используют Java), совместимость с Kafka
- **Kafka**: Обеспечивает асинхронность, защищает АБС от перегрузки, поддерживает event-driven архитектуру
- **Redis**: Решает проблему медленной загрузки справочников
- **MS SQL для депозитного сервиса**: Совместимость с интернет-банком, снижение сложности администрирования
- **Nginx как API Gateway**: Простота настройки, поддержка TLS, rate limiting
#### Логика решения:
- **Изоляция АБС**: Все запросы к АБС идут через Kafka → защита от перегрузки
- **Персонализация ставок**: Депозитный сервис запрашивает данные о клиенте из АБС (через Kafka) при первом обращении и кэширует в Redis
- **Обработка заявок**: 
  - Из интернет-банка: синхронный REST-вызов → Депозитный сервис → Kafka → АБС
  - С сайта: заявка в Kafka → CRM кол-центра → после звонка → Депозитный сервис
- **Отказоустойчивость**: 
  - Интернет-банк и депозитный сервис развернуты в Kubernetes
  - АБС использует active-passive репликацию между ЦОД


### **Альтернативы**  
| Альтернатива                           | Комментарий                                                                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Прямые вызовы АБС (REST)               | **Недостатки:** Риск перегрузки АБС **Отказ:** Не соответствует NFR.                                                            |
| RabbitMQ вместо Kafka                  | **Недостатки:** Меньшая производительность, нет экспертизы **Отказ:** Kafka лучше для масштабирования                           |
| gRPC вместо REST                       | **Недостатки:** Сложность интеграции с legacy **Отказ:** REST проще для .NET 4.5                                                |
| Хранение ставок в отдельной БД (NoSQL) | **Недостатки:** Рассинхронизация с АБС **Отказ:** Выбрано кэширование в Redis + основное хранение в АБС                         |
| Единая СУБД для всех систем            | **Недостатки:** Невозможно из-за разных технологий (Oracle/MS SQL) **Отказ:** Используем оптимальные СУБД для каждого контекста |


### **Недостатки, ограничения, риски**  
1. **Недостатки решения**:
   - **Задержки из-за асинхронности**: Клиент не получает мгновенный результат открытия депозита (до 5 минут). Компенсируется SMS-уведомлением.
2. **Ограничения**:
   - **Интернет-банк на .NET 4.5**: Не поддерживает современные протоколы (gRPC, HTTP/2). Ограничивает производительность.
   - **АБС масштабируется только вертикально**: Риск узкого места при росте нагрузки.
3. **Риски**:
   - **Производительность Kafka**: Неправильная настройка топиков → задержки
   - **Безопасность данных в Kafka**: Передача ПДн без шифрования
   - **Нехватка экспертизы по Kubernetes**: Ошибки развертывания
4. **Компромиссы**:
   - **MVP с ручной обработкой в бэк-офисе**: Автоматизация открытия депозита (без участия менеджера) — следующий этап.
   - **Использование REST вместо gRPC**: Упрощение интеграции ценой производительности.
